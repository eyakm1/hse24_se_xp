# Анализ чистоты кода

Проект по сути своей состоит из двух независимых частей друг от друга: фронтента и бекенда, поэтому анализ будет разделён на две части, для бекенда и для фронтенда.

## Бекенд

Бекенд написан на Go, код логически разделён на модули по директориям:
+ `ports/httpgin` для реализации HTTP сервера на основе фреймворка `Gin`
+ `app/` для реализации логики приложения
+ `/repo` для реализации интерфейса БД

Чистота кода средняя: консистентный нейминг функций и переменных, однако есть некоторые замечания: 
+ Функции не содержат никаких комментариев по функциональности
+ Функции иногда названы несодержательно (например, почти все функции в `adapers/repo/repo.go`) 
+ Некоторые файлы захламлены различной функциональностью (например, `app/app.go`)
+ Код содержит магические переменные, которые никак нельзя изменить пользователю (например, порт сервера)

### Фронтенд

Фронтенд написан на Javascript с помощью фреймворка Vue.js. Код фронтенда также логически разделён на модули:
+ `src/api` для реализации клиента API
+ `src/components/` для реализации различных компонентов фронтенда. Каждый файл -- отдельный компонент
+ `src/pages/` для реализации различных страниц фронтенда. Каждый файл -- отдельная страница в веб-приложении
+ `src/store/` для реализации хранения состояния Web-клиента
+ `src/App.js` реализует маршрутизацию по страницам приложения

Чистота кода высокая:
+ Каждый файл содержит код относящийся только к функциональной единице этого файла
+ Нейминг функций и переменных консистентен и соответствует стандартам проектировки JavaScript

Однако есть и некоторые замечания:
+ Отсутствуют комментарии в коде. Непонятно за что отвечает тот или иной модуль/страница в web-приложении
+ Наличие захардкоженных магических переменных (например, для подключения к бекенду)
